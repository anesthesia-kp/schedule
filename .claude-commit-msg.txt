Build 50 / 26 — small-fix batch: stale-build gate, Quick View, staff error surface, Users lock, audit trail, sticky column

Six independent fixes the owner approved on 16 Aug (DECISIONS §33), plus one
comment correction. No Firestore rules change, so NO Firebase console step.

WHAT CHANGED

1. Stale-build gate — ported from Vacation Auction build 268 (both pages)
   Both pages checked versions.json and then called a bare location.reload().
   If a CDN edge still held the old page, the reload changed nothing — and the
   once-per-version sessionStorage guard had already recorded that version as
   "seen", so the tab never tried again and was stranded on the old build until
   the cache expired or the user hard-refreshed.
   Now: location.replace() to a ?v=<latest> URL, so the edge must re-fetch, and
   the stale page is not left in back history. Plus a re-check when the tab is
   refocused (visibilitychange + focus), throttled to once a minute — an idle
   tab used to sit on the old build until its next 5-minute tick, which is
   exactly when someone returns to it and starts clicking.
   Closes defect 30. The auction's requiredBuilds ratchet was NOT ported.

2. Quick View month boundary (staff 26)
   The next-7-days strip always showed 7 days from today, but assignment data
   was only loaded for the *browsed* month. Paging away turned the whole strip
   into the literal text "view month", and a week straddling a month boundary
   was half blank even on first load. It now subscribes to every month the
   window touches and resolves each day from the right one. The "view month"
   placeholder is gone. Closes defect 11.

3. Staff error surface (staff 26)
   The staff page had NO way to report a failure — 25 silent catch blocks. A
   rejected transaction showed the user nothing at all; the action simply did
   not happen. Added a toast, plain-language messages per Firestore error code
   (permission-denied / unavailable / deadline-exceeded / other), a transaction
   wrapper that reports before rethrowing, and an unhandledrejection guard so a
   handled failure does not also spray the console. Closes defect 14.

4. Users page lock (admin 50) — DECISIONS §20 and §30
   The Users panel writes to the LIVE Vacation Auction's roster: userList,
   usernames, loginEmails, emails, emailToUser. That access stays (owner ruling
   §1) but it no longer sits one stray click away.
   The page opens LOCKED on every load. The lock is in memory, so it re-locks on
   reload rather than remembering an unlock. Unlocking goes through a confirm
   that names the auction consequences in plain words, and the unlock itself is
   written to the audit log. The refusal guard sits at the top of all eight
   mutating handlers, not on the buttons — calling a handler directly while
   locked writes nothing and says so.

5. The writes that used to leave no trace (admin 50)
   postOpen, removeOpen (which now captures what it removed before the
   transaction), and all four per-user field saves — name, login e-mail, KP
   e-mail, FTE — wrote with no audit entry at all. An admin could change
   anyone's Google login address and nothing recorded it. All six are audited
   now, as is the Users-page unlock.

6. Sticky name column on the Schedule Grid (admin 50)
   At ~31 columns the name scrolled out of view and you lost track of whose row
   you were reading. The eligibility grid already did this; the schedule grid
   now matches. Closes defect 19.

7. A comment that was not true (admin 50)
   The Users section carried "// vacations — READ-ONLY: roster, admin list,
   approved vacation weeks" while writing 25 auction documents. Replaced with an
   accurate description. The isolation test now fails if that claim reappears
   while the writes are still there.
