Stage 9. Admin only. Staff page untouched, so staff stays 26.
No firestore.rules change, so NO Firebase console step.

WHAT IT DOES

  Per doctor, for a day / month / quarter / year / custom range:

  1. How many of each shift they did, with OVERNIGHT CALL AT THE TOP, each line
     carrying what they were expected to do at their own FTE and the difference,
     plus subtotals for all overnight call and for all shifts.
  2. A dated list of every overnight call in the period — a list, not a count.
  3. A comparison with the group, adjusted for FTE, with the method printed on
     the page.

  Producible for one doctor or for every doctor in one page-broken document.
  Opens in its own tab, or prints, or exports to a styled .xlsx.

THE OVERNIGHT-CALL TAG — the first admin-defined tag (DECISIONS §25, §27)

  Seeded with the owner's own three: Call 16, Call 24, OB PM. NEVER derived, and
  the test suite proves it behaviourally rather than by inspection: the fixture
  catalog deliberately contains RCH-ICU B (19:30-07:30, crosses midnight) and
  Eye Call (07:30-15:30, in the call family), and asserts that neither is ticked.

  Nothing is written on page load. With no tag document saved, reports use the
  owner's starting set and the page says plainly that it is not saved yet. This
  avoids repeating defect 24 — a one-shot self-marking seeding migration that
  makes later edits to the source constants have no effect.

THE COMPARISON POOL (§35) — and why it is NOT on the Users page

  §29 excludes per diem and locums from the group average and requires the report
  to name who was excluded. Neither was answerable: there is no per-diem or locum
  data anywhere on either page. Groups are stage 4 and not built.

  So each person carries a "counts toward comparisons" flag, defaulting ON, with
  only the exclusions stored — an untouched roster is entirely in the pool and a
  new hire needs no write at all.

  Ruling §35 as first written put that flag on the Users page. It is on the
  REPORTS page instead, with the owner's approval: the Users panel is the one
  place on this site that writes the LIVE Vacation Auction roster, and it opens
  locked for exactly that reason. A schedule-only report setting must never be a
  reason to unlock it.

NO FTE MEANS NO GUESS (§36)

  FTE is optional by design — "no default on this site, ever". A doctor with no
  FTE gets their full report and dated call list, but no expected figure, and
  their block says so in plain words. They do not enter the pool and do not
  affect anyone else's rate. A blank FTE is never quietly treated as 1.0.

THE CALL BASELINE IS KEPT OUT OF DATED REPORTS (§37)

  dailysched/callBaseline is one undated lump per person per shift that decays
  over twelve months. It cannot be apportioned to a chosen period, and it makes
  the same August report give a different answer each month it is run.

  Period reports are therefore pure schedule data and say so. A separate
  "last 12 months — fairness view" is the one place the baseline appears, showing
  exactly what auto-populate sees, stating the _asOf stamp and the weight
  currently applied, and warning that it is not a dated report.

AN UNREADABLE MONTH IS STATED, NEVER SILENTLY ZERO

  A month that fails to read is collected and named in red at the top of the
  report, which marks every number below it incomplete. Quietly treating it as
  empty would print "3 overnight calls" for someone who did nine, with nothing
  on the page to hint at it.

EXCEL (§32)

  Same library, same version and the same construction as the auction's
  exportUserSummary — title row, coloured scope row, timestamp, navy per-person
  banners, bordered and colour-coded cells, auto-sized columns, merged banner
  rows with computed heights, and the identical CSV fallback when the library is
  unavailable.

  The library is fetched only when Excel is actually pressed, NOT in a script tag
  at page load as the auction does it. The eligibility suite caught the first
  cut: a script tag logs a console error on every page load when the CDN is
  unreachable, and that suite asserts zero console errors. The assertion was not
  loosened to accommodate the change; the page keeps the zero network
  dependencies it had.

REPORT_CSS is lifted from the auction admin page VERBATIM, including its internal
comment. The schedule-only classes are appended below a marked divider rather
than edited into the lifted block, and the suite asserts every auction line is
present byte for byte.
